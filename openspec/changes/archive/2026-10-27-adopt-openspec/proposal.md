# Proposal

## Why

This module has no planning system yet: no Agent OS, no OpenSpec, and the sibling modules (`vault`, `keycloak`, `gitlab-management`) already plan changes with OpenSpec against pinned standards stores. Adopting it now gives `scaleway-rdb` a written baseline of its released contract, so later changes (for example unit tests, which do not exist yet, or new inputs) can be written as delta specs instead of being reverse-engineered from `variables.tf`.

## What Changes

- First adoption of OpenSpec (the repository never used Agent OS): `openspec/config.yaml` references the `quality`, `repository` and `terraform` stores and carries scaleway-rdb `context`, `rules` and `operations` guidance.
- Add `AGENTS.md` (project summary, non-negotiables, standards lookup, workflow, precedence, commands) and `CLAUDE.md` importing it; install the `openspec-*` skills for Claude Code (`.claude/skills/`) and OpenCode (`.opencode/skills/`).
- Write the baseline capability specs under `openspec/specs/`, describing the module **as it behaves today**.
- Tooling: pin the `openspec` CLI and `node` in `mise.toml`, add the `spec-validate` and `spec-setup` tasks and `scripts/openspec-setup.sh`, and validate specs in CI through `.gitlab/specs.yml` (`validate:specs`).
- README "Contributing" points to the OpenSpec workflow.
- No change to any `.tf` file, input, output or resource: semver **patch**. Nothing lands in state differently. `CHANGELOG.md` stays generated by git-cliff from commit subjects.

## Capabilities

### New Capabilities
- `module-contract`: supported OpenTofu/Terraform and provider versions, no provider/backend blocks, input names, types, defaults and required/optional split, outputs and the sensitive ones, write-only password handling.
- `instances`: the RDB instance itself: project resolution, engine, node type, region, high availability, storage volume, encryption at rest, engine settings, tags, logs policy and the admin user.
- `databases-and-users`: databases, users with their passwords, and privileges.
- `network-access`: the private network attachment and the ACL rules, including the public-access guard.
- `backups`: automated backup schedule and manual database backups.
- `read-replicas`: read replicas and their endpoints.
